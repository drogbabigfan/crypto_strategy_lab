# v4.8 WFA Pipeline Post-Mortem

## Executive Summary

v4.8 SSL + Fine-tuning 파이프라인 테스트 결과, **모델이 랜덤 수준의 성능**을 보임.
2 fold 만에 Cumulative PnL -65% 도달하여 조기 종료.

---

## 1. 발견된 문제점

### 1.1 Encoder 오염 (Contamination)

**증상**: Fold가 진행될수록 성능 저하

**원인**:
- Phase 2에서 encoder가 unfreeze되어 학습됨
- 같은 encoder 참조가 모든 fold에서 공유됨
- 이전 fold의 학습이 다음 fold에 영향

**해결**: `copy.deepcopy(base_encoder)` 적용

---

### 1.2 Class Weights 폭발

**증상**: Loss가 불안정하게 fluctuation

**원인**:
```
Label Distribution: Short 55%, Neutral 0.03%, Long 45%
Class Weights: [0.60, 1004.3, 0.74]  # Neutral이 1000배!
```

**해결**: `max_weight=10.0`으로 capping

---

### 1.3 Neutral 레이블 부재

**증상**: 3-class classifier인데 실제로 2-class 문제

**원인**: Triple Barrier 설정 문제
```python
sl_mult = 2.0   # SL = 2σ ≈ 0.8%
pt_mult = 2.5   # PT = 2.5σ ≈ 1.0%
max_hold = 100  # 100 bars ≈ 8시간
```

100 bars 동안 가격 변동:
- 최대 상승: 평균 2.49%
- 최대 하락: 평균 3.24%
- **Timeout 확률: ~0%** (항상 PT 또는 SL 도달)

**해결 방향**: max_hold_bars 축소 (100 → 12~24)

---

### 1.4 Model Collapse

**증상**: 모델이 한 클래스만 예측

```
Fold 0: Avg probs [Short: 92%, Neutral: 0%, Long: 8%]  → 100% Short
Fold 1: Avg probs [Short: 0%, Neutral: 0%, Long: 100%] → 100% Long
```

**원인**:
1. 랜덤 초기화에 따라 다른 클래스로 collapse
2. SSL 표현이 방향 예측에 유용하지 않음
3. Fine-tuning이 불안정

---

### 1.5 argmax 편향

**증상**: 확률이 비슷해도 항상 한 쪽만 선택

```python
# Fold 1 평균 확률
Short: 58%, Long: 42%

# argmax 결과
→ 100% Short (Long 선택 안 함)
```

**해결 방향**: Confidence threshold 기반 signal 생성

---

### 1.6 SSL 표현의 한계

**증상**: Encoder frozen해도 Val F1 = 0.33 (랜덤 수준)

**원인**:
- SSL 목표 (Masked Reconstruction)가 **시계열 복원**을 학습
- **가격 방향 예측**과 관련 없는 표현 학습
- Encoder 출력이 분류에 유용한 정보 미포함

**증거**:
```
Encoder Frozen, 50 epochs → Val F1: 0.33~0.35
Encoder Unfrozen, 10 epochs → Val F1: 0.33~0.35
```

둘 다 랜덤 수준. Encoder가 문제.

## 4. v4.9 개선 방향

### 4.1 SSL 제거

```
v4.8: [Features] → [SSL Encoder] → [Classifier Head] → [Prediction]
v4.9: [Features] → [Direct Classifier] → [Prediction]
```

SSL pre-training이 도움이 안 되므로 제거.
처음부터 supervised learning으로 학습.

### 4.2 Sniper Labeling

```python
# v4.8: Loose labeling (거의 모든 샘플이 Long 또는 Short)
max_hold_bars = 100  # Timeout 거의 없음

# v4.9: Tight labeling (확실한 경우만 Long/Short)
max_hold_bars = 18   # 짧은 horizon → 더 많은 Neutral
min_expected_return = 0.45%  # 수익성 threshold
```

목표 분포:
- Long: 30~40%
- Short: 30~40%
- **Neutral: ≥30%** (불확실할 때 거래 안 함)

### 4.3 Confidence-Based Signals

```python
# v4.8: argmax (항상 결정)
signal = argmax(probs) - 1

# v4.9: Confidence threshold (확신 있을 때만)
if max(probs) >= 0.6:
    signal = argmax(probs) - 1
else:
    signal = 0  # Neutral
```

### 4.4 Model Architecture

```python
# v4.8: Channel Independence (각 feature 독립)
PatchTSTEncoder → Linear Head

# v4.9: Channel Mixing (feature 간 상호작용)
PatchTSTEncoder → Channel Mixing MLP → Linear Head
```

## 5. 교훈 (Lessons Learned)

1. **Pre-training task alignment matters**
   - SSL 목표가 downstream task와 align되지 않으면 무용
   - Masked reconstruction ≠ Direction prediction

2. **Label quality > Model complexity**
   - 잘못된 레이블 (Neutral 0%)로는 아무리 좋은 모델도 무용
   - 데이터 → 레이블 → 모델 순서로 점검

3. **argmax is dangerous for trading**
   - 51% vs 49%도 100% 한 방향 결정
   - Confidence threshold로 불확실성 관리 필수

4. **Early stopping on cumulative loss**
   - -50% 도달 시 더 이상 의미 없음
   - 빠른 실패, 빠른 학습

5. **Cross-fold contamination**
   - Stateful 모델 사용 시 deepcopy 필수
   - 매 fold 독립성 보장
